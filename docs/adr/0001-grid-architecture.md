# ADR 0001: Grid architecture

- Date: 2026-10-18. Exact versions were queried from the registry on this date.
- Status: isolated spike; selected composition is conditional, **not production approval**.
- Scope: proofs and documentation. No product UI, shell, Draft, AllUI pointer, workspace dependency or lockfile change by this spike.

[Rule 07](../../.agents/rules/07-grid-spreadsheet.md) and the AGENTS link already cover the product contract, so neither was duplicated. Static metadata and `import('@allsuite/<slug>')` runtime graphs remain separate.

Initial status included unrelated instruction, shell/config, license/lockfile, Draft dialog/CSS and scaffold changes, plus untracked Grid/docs/tests. These were preserved. Actual AllUI checkout is `72ced976ed208e0abd2fbfaf9993aeffce9816cf`; an older rule names another revision, but the pointer and contents were left alone. ## Decision

Compose **React 18 + AllUI + a semantic DOM grid with `@tanstack/react-virtual` 3.14.21 / core 3.19.6; Formualizer 0.11.1 behind a calculation adapter; `fflate` 0.8.3 + `@xmldom/xmldom` 0.9.12 for conservative OOXML overlays**. All are already present in this checkout. No runtime dependency was installed.

Build the domain model, commands, selection and narrow package ownership layer; use libraries for virtualization, ZIP/XML and dependency/recalculation. Do not build a complete spreadsheet engine or use a function collection as one. The overlay is a limited preservation boundary, not a complete XLSX writer. New-workbook export needs a separately tested schema subset. Unsupported edits must be blocked or explicitly reported rather than silently serialized through a lossy normalized model.

**Formualizer is conditional:** real WASM passed in a local browser page but failed under the existing production `script-src 'self'` policy. Future integration must deliberately permit WASM compilation (for example `wasm-unsafe-eval`, verified in workers/production browsers) and audit the Rust dependencies compiled into the artifact. No CSP was changed. If those conditions fail, defer integration or evaluate another permissible full engine; do not substitute HyperFormula or quietly write a full engine.

## Shared suite design

Use **AllUI FullBleedLayout**, as Draft already does in `DocumentWorkspace.tsx`. Its actual API has `children`, `floatingToolbar`, `footer`, `statusBar`, `overlay` and toolbar position. Floating controls overlay content; Draft's command toolbar sits independently above its scroll area and status uses the static footer. Match that allocation rather than covering cells. BoardLayout includes game-board/D-pad/settings behavior and storage preferences, so it is the wrong office frame.

Draft's EditorToolbar composes shared Button, ControlsBar and ToolbarGroup with app-local tablist/tab/tabpanel and keyboard movement. Match its tokens, spacing, focus, tab behavior and EN/PL labels. Command tabs and worksheet navigation need separate labels/keyboard contracts. Keep 44px touch controls, internal scroll, `min-height: 0` and `min-width: 0`.

A future suite-local `OfficeWorkspaceFrame` / `OfficeCommandTabs` in `packages/ui` is reasonable once two concrete consumers and an authorized extraction justify it. Use typed slots for command tabs/panel, optional formula bar, content, sheet navigation and status, without importing editors/format engines. Generic templates/primitives belong upstream in AllUI through its normal release workflow. Do not create an empty shared package, copy AllUI, import Draft runtime into Grid or refactor Draft in this spike. This is a reuse plan, not a product template implementation.

## Model, formulas and preservation ownership

Grid owns one memory-only workbook: stable sheet IDs/order/names, sparse typed cells, canonical formulas plus separate cached results/status, style references, merges/dimensions/date system, selection/history and generation-aware dirty state. OOXML part names and relationship IDs are separate from logical IDs. Retain original parts and mutation journal in memory only. No workbook data, title, filename, previews, handles or history in browser storage; only existing tiny safe UI preferences.

The calculation adapter maps supported cells/functions and owns budgets/unsupported policy; Formualizer owns parsing, dependency tracking, invalidation/order and cycles. Grid owns lexical EN/PL entry/display normalization. Change function tokens, semicolons and decimal commas only in context; preserve quoted strings, escaped quotes/sheet names, ranges and array separators. Store canonical English names/comma arguments separately from locale. Preserve unsupported formula source/cache with explicit stale status, never fabricate a value.

The XLSX adapter owns bounded ZIP/XML preflight, part/content-type/relationship resolution, supported mapping and patching. Preservation means unchanged **uncompressed part bytes and relationships**, not identical ZIP compression or universal consumer compatibility. Unknown content inside a rewritten worksheet needs its own preservation tests. Copying unrelated parts is insufficient if a structural edit invalidates ranges, shared formulas, charts, signatures, pivot caches or relationship targets.

Patch only owned cells/caches. Row/column edits, moves, sheet rename/delete, merges, tables and names need reference/invalidation analysis. Rebuild/remove owned stale calculation chains as required; do not blindly preserve calcChain. Reject archive bombs, traversal/duplicate paths, malformed relationships and DTD/entities before parsing. External/embedded active content never executes or fetches. Block unestablished edits/export or describe the exact loss before an explicitly chosen conversion; no silent lossy save.

Open replaces only after dirty confirmation. Explicit XLSX save cancellation/failure stays dirty; edits during save stay dirty unless in its snapshot. Lazy workers/adapters clean up on session end. No autosave, recent files, telemetry, runtime CDN, network converter or document persistence. PWA caches static assets only and preserves unsaved work during updates.

## Executed proofs

New executable work lives in [review](../spikes/grid/review/), with no shell import. Existing isolated fixtures were reused; [README](../spikes/grid/review/README.md) provides commands.

1. **100x100 logical grid:** Chromium passed scrolling, edit commit, arrows/Tab, Control+End to CV100, accessible grid name/counts and fewer than 500 rendered cells. This is a bounded viewport over 10,000 cells, not 10,000 mounted cells. Old file-URL test failed because ES module loading was blocked; test now uses loopback HTTP. It does not certify React/TanStack performance, screen readers, IME, clipboard or touch targets.
2. **XLSX open/edit/save/reopen:** actual ExcelJS browser build creates two sheets, cross-sheet formula/cache, bold style, merge, validation and note. Proof injects an opaque custom part/relationship and synthetic native pivot graph, edits Input A2 from 5 to 7, saves/reopens through each writer and compares every ZIP entry. [Results](../spikes/grid/review/roundtrip-results.json): ExcelJS and SheetJS dropped opaque plus all five pivot parts; formula cache remained 10. SheetJS also lost bold/validation. Overlay + actual Formualizer produced cache 14, **zero missing entries** and exactly three changed parts (calculation flag/two worksheets), retaining style/merge/note/validation and every other part byte. Directory entries/regenerated shared strings alone are not evidence of data loss; explicit opaque/pivot disappearance is.
3. **Real browser WASM:** existing bridge passed dependency edit/cross-sheet result 10 to 14; two-cell cycle yields CIRC; `=SUMA(Input!A1;1,5)` normalizes to `=SUM(Input!A1,1.5)` and evaluates to 8.5. Observed requests stayed on loopback. A second passing test demonstrates the production CSP blocker; it does not claim production initialization works.
4. **Earlier contract fixtures:** isolated Vitest config passed three toy formula tests and one raw package test. These are lower-strength evidence than actual engine/writer runs. Both spike TypeScript configurations passed.

Pivot XML is a synthetic retention probe, **not schema validated or reopened in a genuine spreadsheet consumer**. ExcelJS reopening is independent parsing, not Excel/LibreOffice certification. No real chart fixture or pivot authoring was proved. Overlay byte retention does not establish semantic correctness after structural edits.

## Pivot strategy

No selected component provides verified native pivot authoring. A grouped summary is not a pivot. Start later with one internal source range/table, row/column/value fields, sum/count and saved visible output. Preserve existing graphs when safe; mark caches refresh-required and report stale results. Block structural edits that invalidate unsupported pivot references.

| Owner                                        | Required graph for first supported saved-cache subset                                                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `xl/workbook.xml`                            | `pivotCaches/pivotCache` with unique cacheId and relationship ID.                                                                                       |
| Workbook `.rels`                             | pivotCacheDefinition relationship to cache definition.                                                                                                  |
| `xl/pivotCache/pivotCacheDefinitionN.xml`    | Source range/table, field names/types/sharedItems, record count, records relationship ID and refresh policy.                                            |
| Cache definition `.rels`                     | pivotCacheRecords relationship to records part.                                                                                                         |
| `xl/pivotCache/pivotCacheRecordsN.xml`       | Typed records/shared-item indexes consistent with source and cache fields.                                                                              |
| Worksheet XML and `.rels`                    | pivotTableParts/pivotTablePart and pivotTable relationship; saved display cells match location/layout.                                                  |
| `xl/pivotTables/pivotTableN.xml` and `.rels` | Name/cacheId, location, pivotFields/items, row/column fields/items, dataFields/aggregates/formats as applicable; relationship back to cache definition. |
| `[Content_Types].xml`                        | Correct pivotTable, pivotCacheDefinition and pivotCacheRecords overrides. IDs, targets, counts and indexes agree.                                       |

[Open XML overview](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-pivottables) describes the graph. Other valid strategies can omit saved records; this subset deliberately writes offline cached data. `fullCalcOnLoad` alone does not refresh pivots. Fixture has `refreshOnLoad=1`; consumer refresh is not implemented. Overlay retained its graph, both writers dropped it. Authoring requires schema checks and real-consumer reopen before any support claim.

## Unresolved risks

- WASM CSP integration and full compiled Rust/runtime/asset license closure block production approval. Measure initialization/memory/worker cancellation and confirm PWA precache limits include the 9.84 MB binary offline.
- Manual screen-reader support, virtual active-descendant retention, IME, touch, clipboard, large selections and representative sheet sizes remain unverified. No broad visual audit was appropriate for this spike.
- Formula parity needs date-system/leap-year, errors/coercion, volatile functions, dynamic/shared/array formulas, names, unknown functions and external-reference fixtures. One PL example is not full tokenization certification.
- Strict OOXML, encryption, signatures, macros/OLE, connections, threaded comments, charts/drawings, slicers, rich text and extensions are not claimed editable/preserved in all cases. Pass-through never implies execution or editable support.
- Overlay reference/style/shared-string ownership can grow expensive. Re-evaluate a maintained preservation-focused library if that boundary expands, using these fixtures first. The earlier untested office-kit writer proposal is not adopted.
